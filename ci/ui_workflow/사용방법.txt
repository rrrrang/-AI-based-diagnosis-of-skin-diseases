실제 환자·의사 UI 연결 검사

SkinAI-Workflow-CI에서 실제 서비스 연결 흐름을 검사합니다.
환자 화면에서 사진을 접수하고 실제 모델 3개가 분석한 뒤, 의사 화면에서
임시 저장·최종 확정하고 환자에게 공개되는 내용을 확인합니다.
이 작업 자체는 이미지 업로드나 배포를 하지 않습니다. 성공 결과는 같은 main 커밋의
UI·Backend 결과와 함께 SkinAI-Release-CI의 업로드 조건으로 사용합니다.

준비
- D드라이브 작업 폴더를 사용하는 Windows Jenkins 실행 환경
- Docker Desktop, Python 3.12 이상, Node.js, 미리 설치한 Playwright Chromium
- skinai-backend-ensemble:20261113 로컬 이미지
- MobileNet·ResNet50·YOLO 모델 폴더와 개인정보가 없는 검사 가능한 근접사진
- 현재 이미지의 /srv/support에는 worker_entry.py, worker_health.py와
  모델 해시·worker 준비상태 검사 코드가 포함되어 있습니다.
  다른 PC에서는 모델 파일만으로 실행되지 않으며 동일한 이미지와 모델 묶음이 필요합니다.
- 설치된 Playwright 버전에 맞는 Chromium을 준비합니다.
- 18165 / 18166 / 18167 포트가 비어 있어야 합니다.
- Docker Compose는 env_file의 required: false 설정을 지원해야 합니다.

Jenkins의 main 전환 설정
아래는 준비한 전환 기준이며 아직 실제 Jenkins 변경을 뜻하지 않습니다.
- 작업 이름: SkinAI-Workflow-CI
- 작업 종류: Pipeline
- Definition: Pipeline script from SCM
- SCM: Git. 기존 저장소 주소와 저장소 읽기 권한을 선택합니다.
- 검사할 브랜치: */main
- Script Path: ci/ui_workflow/Jenkinsfile
- ci/release/README.md의 전환 순서에 따라 main 반영과 네 작업의 SCM 설정을 함께 맞춥니다.
- 기존 두 서버 CI·CD와 해당 복구 기록은 그대로 유지합니다.
- 이 작업은 5분 간격으로 저장소 변경을 확인하며, 같은 작업의 동시 실행을 막습니다.
- 실행마다 별도 Git 복사본을 가져오며 실제 검사한 브랜치와 커밋을 revision.txt에 남깁니다.
- 기본 경로는 Jenkinsfile에 있으며 필요할 때 CI_PYTHON_EXE, CI_DOCKER_EXE,
  CI_NODE_DIR, CI_BROWSER_DIR, CI_MODEL_DIR, CI_SAMPLE_FILE, CI_WORKFLOW_IMAGE로 바꿉니다.
  새 작업 폴더, 임시 파일과 npm 캐시는 D드라이브에 둡니다.

Jenkins 검사와 기록
- 먼저 정리·중단 복구 검사 23개를 실행합니다. 이 검사는 실제 Docker 서버를 사용하지 않습니다.
- 그다음 실제 UI·API·MobileNet·ResNet50·YOLO를 연결한 브라우저 흐름 2개를 실행합니다.
  각각 사진 2장과 3장을 접수하고, 의사의 사진 조회·임시 저장·최종 확정과 환자 결과를 확인합니다.
- 검사 성공·실패·중단 모두 이번 실행의 테스트 컨테이너만 정리합니다.
- 정리와 토큰 가림 처리를 확인한 경우에만 JSON 보고서와 로그를 Jenkins에 보관합니다.
  확인하지 못하면 커밋과 일반적인 정리 상태만 보관하고 실행 폴더를 남깁니다.
- 사진, DB, 임시 인증파일, 브라우저 화면·동영상·추적 기록은 보관하지 않습니다.
- 정리와 기록 보관이 성공하면 실제 경로를 확인한 뒤 이번 runs/빌드번호 폴더만 삭제합니다.
  다른 실행 폴더는 지우지 않습니다. 정리에 실패한 폴더는 복구 확인 전까지 남겨 둡니다.
- Jenkins에는 최근 빌드 기록 10개를 보관합니다.
- 성공 여부는 summary.json의 PASSED와 workflow-2-photos.json 및
  workflow-3-photos.json의 passed, jenkins-status.txt의 정리 상태로 확인합니다.

PowerShell 실행 예시 (본 PC)
검사할 체크아웃에서 ci 폴더가 보이는 프로젝트 최상위 폴더에 터미널을 엽니다.
$env:PYTHONUTF8='1'
$env:npm_config_cache='D:\SkinAI_DevOps\npm-cache'
$env:TEMP='D:\SkinAI_DevOps\workflow-temp'
$env:TMP=$env:TEMP
New-Item -ItemType Directory -Path $env:TEMP -Force | Out-Null
& 'D:\miniconda3\python.exe' '.\ci\ui_workflow\run_workflow.py' --models 'D:\SkinAI_DevOps\ensemble_docker_check\models' --sample 'D:\SkinAI_DevOps\backend_ensemble_check\samples\sample.png' --output 'D:\SkinAI_DevOps\ui_workflow_verification_next' --docker 'C:\Users\human\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe' --node-dir 'D:\SkinAI_DevOps\tools\node-v24.22.2-win-x64' --browsers 'D:\SkinAI_DevOps\playwright-browsers'

--output은 매번 새 폴더 이름을 사용합니다.
실행 순서: 패키지 설치 → 별도 API/worker 실행 → 두 UI 빌드 → 2개 브라우저 검사 → 테스트 컨테이너 정리.
결과는 --output 아래 results 폴더에 있습니다. summary.json이 PASSED이고 두 workflow JSON이 passed인지 확인합니다.
로컬 실행 결과 폴더는 Jenkins와 달리 자동으로 삭제되지 않습니다.
입력 사진 형식 검사는 기존 tests/e2e/patient-required-input.spec.ts에서 따로 실행합니다.

중단된 로컬 실행의 정리 재시도 예시
& 'D:\miniconda3\python.exe' '.\ci\ui_workflow\run_workflow.py' --cleanup --output 'D:\SkinAI_DevOps\ui_workflow_verification_next' --docker 'C:\Users\human\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe'

--cleanup은 해당 실행의 state.json과 Compose 소유 정보를 검사한 뒤 그 실행의 자원만 정리합니다.
실행 폴더나 소유 정보를 바꾸지 말고 원래 --output 경로를 지정합니다.
Jenkins 정리에 실패했다면 보관된 jenkins-status.txt와 남은 실행 폴더를 확인합니다.

주의할 범위
- 실제 AI 정확도·의료 적합성을 평가하는 검사가 아닙니다.
- 정면 합성 이미지 및 근접 샘플을 사용하며 실제 정상/HOLD 모두를 보장하지 않습니다.
- 모델·원천 사진·임시 인증파일·생성된 DB는 Git에 올리지 않습니다.
